# P2 단일 요청자 쓰기 전체 재측정

## 승인·고정 조건

사용자는 기존 읽기 E-16/E-21·전체 viewport 결과를 유효로 인정했다. 쓰기는 무효 B2만 교체하지 않고 **새 세션에서 A1/B 5쌍 전체**를 다시 실행한다. [기존 결과·무효 표본](P2_RESULTS.md)은 삭제하거나 새 표본과 합치지 않는다. P3는 진행하지 않는다.

- AB/BA 교대: A1/B, B/A1, A1/B, B/A1, A1/B. 단일 VU, 매 실행 새 JVM, 예열10+측정30 CRUD 주기. 총400주기/1,200 HTTP(본900·예열300).
- 기존 M 편향 seed·앱/DB/k6 이미지·CPU/메모리·heap·Hikari·PG 설정·간섭 판정은 불변. 새 Compose 프로젝트·결과 폴더 `*-write-retest1`을 사용해 이전 DB·원본을 보존한다.
- A1 SHA256 `da87c44168c321d1b05c5d3bbf61a459284c937fdd145c93aa6e940fff1d1a60`, B `639c3956667040fde1072d922d614c4b8a96c7c78c554957d9042c89175cef5e`. 애플리케이션 변경·재빌드 없음.
- 판정: 모든 예열/본 측정 유효·오류0·dropped0·업무 DB 복원, 쓰기 회귀10% 이내. 기존 p95 반복 변동 폭/중앙값10% 초과 시 승자를 선언하지 않는 규칙도 유지한다. endpoint당 회차30개로 p99는 작은 표본의 탐색값이다.
- 사용자 환경 확인 완료: 전원 연결·최고 성능·절전 해제·업데이트 일시 중지, **브라우저 포함 무거운 앱 종료 및 측정 중 미사용**. 시작/회차별 프로세스·전원 상태를 기록한다. 노트북 상대 비교이며 운영 절대 수치가 아니다.
- 같은 배경7개는 pause/unpause만 사용한다. before→paused→restored 상태를 별칭으로 남긴다. finally·부모 종료 감시자가 실패/중단에도 복구하며 마지막 직접 inspect로 모두 running인지 확인한다.

## 실행 전 시간 추정

이전 단일VU10회 측정 단계(스냅샷·수집 포함)의 합은 **953.462초**다. 여기에 기동10회×30초, 새 DB 시드/검증2회×60초, pause/복구60초를 더하면 **1,433.462초(23.89분)**다. 호스트 준비 편차를 포함해 **24~30분**으로 예상한다. 분석·문서화·업로드 시간은 별도다. 이 추정은 부하 시간이나 반복 수를 늘리는 설정이 아니다.

```powershell
$env:PERF_HEAVY_APPS_STATUS='closed-user-confirmed'
node perf/stage2/p2-session.mjs write-retest
# 비정상 종료 뒤 수동 복구가 필요한 경우에만
node perf/stage2/p2-session.mjs restore write-retest
```
