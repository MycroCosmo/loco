# E-24 B — 반복성과 회귀 판정을 분리한 마지막 쓰기 세션

## What·Why: 결과 확인 전에 승인한 규칙

사용자는 E-24 B를 **향후 실행부터** 적용하도록 승인했다. E-23과 이전 두 쓰기 세션의 수치·판정·원본은 그대로 보존하고 새 규칙을 소급 적용하지 않는다. [첫 P2](P2_RESULTS.md), [30표본 재측정](P2_WRITE_RETEST.md), [E-23 300표본](P2_WRITE_E23.md)을 이번 결과와 병기한다.

승인 근거는 읽기 회차당 약15,000표본에 사용한 편차10% 규칙과 쓰기 비교 목적을 구분하는 것이다. E-23의 큰 편차는 A1 생성 p95의 회차 순서에 따른 단조 이동(164.930→144.105ms)에서 나타났다. 당시 전체5쌍 기술통계의 효과 크기 약−87~−93%는 반복 편차 약6~19%보다 컸다. 이 관측은 A1 이동을 만든 JIT·캐시·호스트 등의 기계적 원인을 증명한 것은 아니다. E-23의 무효 예열을 유효로 바꾸는 근거도 아니다.

## 고정된 판정

1. **회귀 필수 조건:** 생성·이동·삭제·혼합 각각, **5쌍 모두 `B p95 / A1 p95 ≤ 1.10`**이어야 한다. 4종×5쌍=20개 비율을 공개한다. 중앙값으로 나쁜 쌍을 상쇄하지 않는다. 부트스트랩·신뢰구간은 사용하지 않는다.
2. **반복성 품질 경고:** 각 side·작업별 p95 `(max−min)/median > 10%`이면 경고로 기록한다. 이 조건만으로 판정을 막지 않는다.
3. **유효성 필수 조건:** 예열·본 측정의 간섭, HTTP/검사 오류, dropped, 관측 실패, DB 복원 실패는 해당 시나리오를 무효로 한다. 무효·불리한 표본을 제외하거나 대체하지 않는다. 기존 간섭 규칙은 불변이다.
4. **한 번만 실행:** 새 세션 전체5쌍을 한 번 실행한다. 무효가 나오더라도 가능한 나머지 정해진 회차는 기록하며 자동 재시도는 하지 않는다. 업무 검증 실패로 실행기가 중단되면 복구 후 원본과 중단 상태를 기록한다.
5. **종료 판정:** 유효성 및20개 비율이 모두 통과하면 기존 읽기·전체 viewport 승인과 합쳐 **P2 최종 채택**을 기록한다. 또 무효가 나오면 **“읽기·전체 viewport 채택, 쓰기는 개선 방향 확인·정량 판정 보류”로 P2를 마감**하고 추가 반복하지 않는다. 유효하지만 비율이 실패하면 쓰기 회귀 미통과로 보류하며 추가 실행 없이 보고한다. 어느 경우도 P3로 진행하지 않는다.

실행 manifest의 `writeSpec`은 쓰기 표본 수, `adoptionPolicy`는 E-24 B 판정을 기록한다. 기존 공유 `protocol`의 읽기 설정을 쓰기 판정으로 오해하지 않는다. 이전 모드의 편차 hard gate는 그대로 남겨 과거 분석을 재현한다.

## How — 마지막 쓰기 세션 결과와 P2 마감

**읽기·전체 viewport 채택, 쓰기는 개선 방향 확인·정량 판정 보류.** E-24 B는 실행 전 [d3526bb](https://github.com/MycroCosmo/loco/commit/d3526bb8532ea0575680b43d6c0f43c6da3eb38e)로 커밋·push했다. 새 세션을 한 번만 실행했고, 아래 간섭으로 유효성 필수 조건을 충족하지 못해 P2를 이 상태로 마감한다. 재시도·대체·제외·추가 진단·P3 실행은 하지 않았다.

- 실행·복구: **2026-11-09 23:45:00.520 ~ 2026-11-10 00:24:01.140 KST**, **2340.620초(39분 0.620초)**. 사전 예상36~42분 안이다.
- A1/B5쌍·예열10+본300 CRUD 완료. **20구간 중15유효/5무효**, 예열과 본을 묶은 **10개 실행 시나리오 중6유효/4무효**.
- HTTP **9,300건**(본9,000·예열300), 오류·검사 실패·dropped **0**. DB 복원 **10/10**, OOM0.
- 작업4종×5쌍 **20개 p95 비율 모두≤1.10**. 하지만 유효성은 별도 필수 조건이므로 이것을 정량 채택으로 해석하지 않는다.
- side별 반복성 경고 **8건**. E-24에서는 경고만이며 이번 보류의 원인은 **간섭**이다. 부트스트랩·신뢰구간은 계산하지 않았다.

상위 비측정부하 프로세스에는 ChatGPT·codex·Installer·Chrome·codex-computer-use·Docker Desktop이 관측됐다. 전원/최고 성능 변경·메모리 압박·수집 누락·배경 컨테이너 재개는 무효 사유로 발생하지 않았다. 사용자 환경 확인과 실제 관측을 각각 기록하며, 이 자료로 수동 조작 여부나 응답 지연의 인과를 확정하지 않는다. 사후 허용 목록 추가·간섭 기준 변경은 하지 않았다. 세부 타임스탬프와 상위 CPU/메모리 목록은 원본 `host.jsonl`, 세션 `interference-evidence.json`에 있다.

배경7개는 `running→paused→running`. 자동 finally 복구 후 **2026-11-10 00:24:37.877 KST** 별도 Docker inspect에서7개 모두 `Running=true/Paused=false/Status=running`을 확인했다. stop/rm/볼륨 변경 없이 pause/unpause만 했다. 이전세션 **4,796파일 크기·mtime, 쓰기 관련847개 SHA256 불변**을 검증했다.

- A1: HTTP 4.810~5.522req/s, 앱 CPU 평균 0.076~0.088코어, 앱 working set 최대 491.42MiB, DB 401.28MiB.
