# P2 정식 측정 — 읽기 기준 통과, 쓰기 표본 간섭으로 최종 채택 보류

**후속(2026-11-09 22:21 KST):** 사용자가 읽기·전체 viewport를 유효로 인정한 뒤, 쓰기 전체5쌍을 새 세션에서 재측정했다. 20구간 모두유효·HTTP1,200건 오류0이나 p95 반복 편차 미달로 최종 채택은 계속 보류한다. [새 재측정 결과](P2_WRITE_RETEST.md). 아래 첫 세션 수치·판정과 원본은 당시 기록으로 보존한다.

2026-11-09 로컬 노트북에서 고정된 E-16/E-21 기준으로 측정했다. **1% 회귀·10% 개선·전체 viewport OOM 검사는 통과했지만, 필수 쓰기 표본 한 회차가 간섭으로 무효여서 P2 전체 채택은 보류한다.** 기준·부하·힙을 바꾸거나 무효 회차를 대체하지 않았다. P3는 진행하지 않는다.

[상세 설계·승인 이력](../../apps/server-v3/PERF_STAGE2_P2_DESIGN.md), [기계 판독 결과](results/p2-formal/analysis.json), [manifest·복구 증거](results/p2-formal/manifest.json), [압축 원본 Release](https://github.com/MycroCosmo/loco/releases/tag/perf-stage2-p2-20261109-formal).

## 1. What·Why

P1의 좌표 정합성과 E-12 표시 순서를 유지하면서 E-16의 작은 범위 회귀를 회복하고, 넓은 범위에서 모든 셀을 Java 객체로 만들던 비용을 줄인다. 쓰기는 이전/새 셀 집계를 결합하고, E-22의 지도방+정밀도별 잠금 SELECT를 먼저 실행해 교착·오래된 집계를 막는다.

이번 B는 `91d653a`에서 검증한 JAR다. 조회는 최대301 후보 뒤 실제 반환 분기에서만 ROUND를 계산하고, 셀은 ≤699에서 Java 정렬, ≥700에서 같은 DB snapshot의 top699+overflow를 반환한다. 중심 좌표만 승인된 ≤1e-10 허용이며 count·셀 키·표시 집합·배열 순서는 기존 비교 계약을 유지한다.

읽기 비교를 다시 실행하거나 무효 표본을 자동 대체하는 명령이 아니다. JFR 공개본은 `--stack-depth 0`으로 필요한 메모리 이벤트만 추출했다. 바이너리 원본은 로컬에 보존하고, private·자격증명·준비 응답 캐시는 공개 압축에서 제외한다. 각 압축에 SHA256SUMS와 redaction 설명이 있다. 상세 호스트 프로세스에는 명령줄·환경변수 값이 없고 다른 프로젝트 컨테이너는 별칭만 남긴다.
