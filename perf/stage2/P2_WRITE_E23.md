# E-23 쓰기 표본 확대 — 실행 전 고정 프로토콜

## What·Why

사용자가 결과를 보기 전에 E-23을 승인했다. 회차당 endpoint30표본의 p95는 작은 꼬리 표본에 민감하므로, 읽기 회차당 약15,000표본에 적용하던 상대 편차10% 규칙을 쓰기에 판정하기 위한 추정 정밀도가 부족하다는 문제다. 현재 선형 보간은 `(n-1)×0.95` 위치를 사용한다. n=30이면 1기준28.55번째, 즉 **상위2~3번째 사이**이고 n=300이면285.05번째(상위15~16번째 사이)다. 작은 표본의 한계를 기록하며 이것이 지난 편차의 유일한 원인으로 증명됐다고 주장하지 않는다.

이번에는 **예열10+측정300 CRUD**로 표본만 확대한다. 과거 수치를 새 결과로 교체하지 않으며 [첫 정식 세션](P2_RESULTS.md), [30표본 재측정](P2_WRITE_RETEST.md), 이번 E-23을 병기한다. 다른 프로토콜의 값을 합산하지 않는다.

## How — 변경·불변 조건

- A1/B 단일VU5쌍, AB/BA 교대: AB·BA·AB·BA·AB. 매 실행 새 JVM, 각10예열+300본CRUD. endpoint별 본300표본, 회차당 본HTTP900건. 전체 본9,000+예열300=**9,300 HTTP**,3,100CRUD.
- A1 원래 JAR SHA256 `da87c44168c321d1b05c5d3bbf61a459284c937fdd145c93aa6e940fff1d1a60`, B `639c3956667040fde1072d922d614c4b8a96c7c78c554957d9042c89175cef5e`. 앱 코드·JAR·이미지 불변, 재빌드 없음.
- 기존 seed M편향·100,000장소/1,000지도방·hot방50,000장소, 같은 분리셀 생성→이동→삭제, DB fingerprint 복원 검증. 새 프로젝트와 결과 폴더 `*-write-e23`로 격리한다.
- 앱 CPU2/1.5GiB, DB CPU2/4GiB·shared_buffers1GiB, k6 CPU2/2GiB. 기본힙389,283,840바이트·SerialGC·Hikari10·work_mem4MB·대표측정SQL추적off. k6 기존maxDuration10분 유지. 300완료 전 timeout이면 실패이며 표본수를 줄이지 않는다.
- **편차10%·쓰기 회귀10%·간섭 규칙 불변.** 회차별percentile5개의 중앙값·range/median·paired변화를 모두 기록한다. 모든 예열/본측정 유효·오류0/dropped0·업무DB복원 필수. p99는300표본에서도 탐색값이다.
- 간섭: 배경CPU2코어 초과10초 이상, 가용메모리2GiB 미만10초 이상, 전원/성능모드 변경, 관측간격10초 초과, 수집실패/누락 또는 배경컨테이너 실행이면 무효. 기존 수집기·예열/본창 앞뒤 관측을 그대로 쓴다. 무효/불리한 회차 자동 교체 없음.
- 사용자가 AC·최고성능·절전해제·업데이트중지·브라우저 포함 무거운앱 미사용을 확인했다. 호스트전원·상위CPU/메모리 프로세스·WSL상태를manifest에 기록한다. **노트북 상대 비교이며 운영 절대수치가 아니다.**
- 같은 배경7개만 pause/unpause한다. before/paused/restored 별칭·상태, finally/부모종료watchdog, 종료후 직접inspect로7개running 확인. 해당7개 stop/rm/볼륨변경 금지.
- 이미 승인된 읽기E-16/E-21·전체viewport는 재측정하지 않는다. READ_COMMITTED 명시의 JDBC SHOW요청당3회는 기존 후속메모만 유지하고 코드는 바꾸지 않는다.

## 실행 전 시간 추정

직전 재측정 전체1,315.290초, 그중 본HTTP창10회 합94.705초였다. 나머지 기동/예열/시드/수집/스냅샷/복구를 그대로 두고 본표본을10배로 늘리면 `1315.290+94.705×9=2167.635초`(**36.13분**)다. 편차와 준비 여유를 포함해 **36~42분**을 예상한다. 분석·문서·업로드는 별도다. 예상보다 빠르거나 느리더라도 부하·횟수·기준을 변경하지 않는다.

```powershell
$env:PERF_HEAVY_APPS_STATUS='closed-user-confirmed'
node perf/stage2/p2-session.mjs write-e23
# 실패/중단 뒤 복구 확인이 필요할 때만
node perf/stage2/p2-session.mjs restore write-e23
```

## 중단·채택 규칙

300표본에서도 기존 편차 기준을 넘으면 **최종 채택 보류**로 멈추고 **E-24 쓰기 편차 기준 설계**를 새 결정 항목으로 제시한다. 새 기준을 이번 결과에 소급 적용하지 않고 추가 반복도 하지 않는다. 모든 기존 기준을 통과한 경우에만 P2 최종 채택을 기록한다. 어느 쪽이든 P3는 진행하지 않는다.

결과는 실행 완료 후 아래에 추가하며 이전 두 세션 원본을 보존한다.
