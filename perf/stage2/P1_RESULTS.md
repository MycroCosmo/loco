## What · Why — 바뀐 동작

PG numeric ROUND·0 정규화를 쓰기·집계·마커 그룹 생성/역조회에 적용했다. Java 응답용 좌표가 아닌 저장된 float8이 기준이다.37.05→37.1,-0.00001→0.0으로 셀 누락을 막는다. V7은 기존 장소·스키마 형태·V1을 보존하며 파생 셀을 재생성한다. 실패 시 기존 셀과 Flyway 이력이 함께 롤백된다.

count 동률은 `cellLatKey COLLATE "C" ASC, cellLngKey COLLATE "C" ASC`로 정렬한다. 표시699개와 overflow 멤버십/중심이 물리적 행 순서에 따라 바뀌지 않는다. 숫자 정렬이 아닌 명시적 문자열 순서다. 기존 전체 셀 물질화, 갱신6/12SQL, 장소 커밋과 재집계 분리·경합은 유지했다.

v2 fixture는 그대로 두고 `markers.pg-coordinate-rule`과 `markers.deterministic-overflow`를 개선 차이로 추가했다. **현재13건=개선8·의도5·보류0**, 이관 당시11건은 역사적 기록으로 보존한다. 성능 미달을 API 알려진 차이로 바꾸어 통과시키지 않는다.

## 실행 시간과 판정 한계

최초 예상은 구현 제외110~125분이었다. 후보 실패 재검증·예열 조사·두 JFR·추가 상한 탐색이 늘어 예상 범위를 넘었다. 각각 실행 전에 추가 계획을 기록했으며 실패 회차도 합계에 포함했다.

자원 수집 최초~최종은 KST **2026-11-08 23:08:52~11-09 01:57:54**, **169분2.3초**다. 이 span에는 준비·fingerprint·조사·작업 간격이 포함되며 부하 명령 합계와 다르다. 그 전에 수행한 최초 실패 회귀1,130.133초와 집중 검증120.672/72.707초도 별도 보존했다. 구현·모든 준비까지 포함한 총 작업 시간을 계측했다고 주장하지 않는다.

**다음 채택 판정의 선행 조건:** 예열/재기동 계약을 고정한 동일 세션 대조로1% 회귀와10% 편차를 분리하고, 그룹 ROUND 역조회의 인덱스 사용을 검토해야 한다. 이번 결과로 성능 개선율·최대 운영 용량·PostGIS 우열을 선언하지 않는다. P2·P3 구현 없이 여기서 멈춘다.
