# 전체 회귀 시간과 재시작 조건

Windows Java 21·Gradle 8.14.6·Docker Desktop, v2 이미지와 Prisma/libvips 도구 캐시가 있는 상태에서 측정했다. 각 실행은 빠른 테스트와 전체 비교 테스트, 포맷 검사와 빌드를 포함한다. 단일 실행의 wall time이며 부하가 다른 환경의 성능 보장은 아니다.

이전 작업 기록은 955.571초·v2 재시작 321회다. 당시에는 구간 계측이 없어 그 시간을 소급 분해할 수 없다. 이번 동일 계측 전후는 아래와 같다. 재측정 전 총시간이 이전 기록보다 길어진 이유를 특정 구간의 회귀로 단정하지 않는다.

| 구간 | 개선 전(초) | 개선 후(초) |
| --- | ---: | ---: |
| v2 재시작·HTTP 준비 | 750.387 | 13.482 |
| DB 초기화·시드·메일 비우기 | 59.870 | 55.383 |
| 실제 HTTP 요청(아래 이미지 구간 제외) | 34.803 | 26.399 |
| 이미지 메타데이터·변환·저장 | 16.718 | 14.717 |
| 기타 | 400.090 | 357.705 |
| 전체 | **1261.867** | **467.687** |

동일 계측 전후 794.180초(62.94%) 감소했다. 기존 955.571초 기록과 비교하면 51.06% 짧다. 기타에는 Gradle·컨테이너 최초 기동/종료·Spring 기동·DB 스냅샷 비교·Node 검증·파일 fixture 준비·독립 코덱 probe 등이 포함된다. 이 안의 세부 비용은 아직 분리 측정하지 않았다. [계측 경계](COMPARISON_TESTS.md#실행-시간-계측)를 참고한다.

## 재시작 원인과 변경

기존 CompatibilityTestBase의 BeforeEach는 usesV2Http=true인 모든 케이스에서 무조건 restart했다. 요청 제한에 걸리는지를 판단하지 않았다.
실제 v2 이미지의 ThrottlerGuard.generateKey는 컨트롤러·핸들러·기본 throttler 이름·IP로 키를 만든다. 따라서 기본 120/분도 애플리케이션 전체 공용 한도가 아니다. 다른 지도 ID나 OAuth provider는 같은 핸들러 한도를 공유하며, 같은 URL의 GET/PUT은 다른 핸들러다. 이 동작은 새 필수 HTTP 비교로 검증한다.

현재는 v2가 반환하는 실제 키·경로 패턴·잔여 횟수를 관측한다. 첫 요청의 잔여량이 없거나, 429 경계 검증에 초기 한도가 필요하거나, 동시 요청에 필요한 슬롯이 부족할 때만 시나리오 시작 전에 재시작한다. 오류 응답을 받은 뒤 재시도하지 않는다. 깨진 JSON처럼 Guard 이전 거절은 소비한 요청으로 세지 않는다. 시나리오 도중 소진되면 재시작 대신 만료를 기다린다.

개선 후 실제 6회:

| 사유 | 횟수 |
| --- | ---: |
| 동시 재설정 2개 슬롯 확보 | 1 |
| reset-password 잔여량 소진 | 1 |
| forgot-password 잔여량 소진 | 1 |
| forgot-password 429 경계 검증의 초기 한도 확보 | 1 |
| 핸들러 독립성 검증의 login 10개 슬롯 확보 | 1 |
| login 429 경계 검증의 초기 한도 확보 | 1 |

인증 외 API 재시작 0회, 시나리오 내부 대기 0ms였다. 준비용 JWT 직접 서명, DB 초기화와 전체 스냅샷 비교, 필수 429·동시 요청·이미지 검증은 유지한다. v2 운영 소스·요청 제한값·IP를 바꾸지 않았다.

## 검증 범위와 재현

- 기존 437건에 계측 계산 2건을 추가한 개선 전: 전체 439, 성공 438, 실패 0, HEIC 코덱 제약 SKIPPED 1. 비교 327건 모두 성공.
- 개선 후: 전체 447, 성공 446, 실패 0, 같은 SKIPPED 1. 빠른 119건 중 118 성공, 비교 328건 모두 성공.
- 전후 테스트 식별자 목록 대조: 기존 케이스 누락 0, 새 quota 단위 7건·실제 핸들러 한도 비교 1건 추가. 기존 알려진 차이 4건은 별도 보고하며 수가 같다.
- 수정안의 선행 검증: 단위 9건·429/비밀번호 재설정 비교 26건, 총 35건 모두 성공(Gradle 표시 71초).

앱 디렉터리에서:

```powershell
pwsh -File scripts/measure-tests.ps1 -Label before -RestartMode each-case
pwsh -File scripts/measure-tests.ps1 -Label after -RestartMode quota
Compare-Object (Get-Content build/performance/before/test-manifest.txt) (Get-Content build/performance/after/test-manifest.txt)
```

스크립트는 test/comparisonTest를 실제 재실행한다. 원본 로그·시간·테스트 식별자는 build/performance/<Label>/에 있다. 기록한 before는 하네스 회귀 8건을 추가하기 전 실행이므로, 현재 코드로 each-case를 재현하면 추가된 테스트도 함께 돈다. 기본 gradlew test/comparisonTest/allTests/build의 검증 범위는 그대로다.
